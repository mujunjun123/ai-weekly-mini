# 实施状态与安全

本地已实现，尚未云部署、微信真机验证或发布。已配置 AppID。此前聊天中暴露的 AppSecret 必须在微信公众平台重置；本项目没有使用 AppSecret 的场景，无需向开发者提供新密钥。不要提交 .env 或私有配置。

## 推荐低成本路径：复用已有 Linux 主机

不自动购买任何资源。已有主机运行每小时 Python 采集和只读 API，无数据库、无模型调用。费用取决于现有主机、域名和流量，不能承诺免费。

1. 将项目放到 /opt/ai-weekly-mini；创建普通用户 weekly 并使该用户拥有项目 data、preview、miniprogram/utils 写权限。创建 .venv 并安装 requirements.txt。
2. 以 weekly 用户执行 `.venv/bin/python scripts/update.py` 生成第一份快照。
3. 管理员检查 deploy 下三个 systemd 单元，复制到 /etc/systemd/system 后执行 daemon-reload，再启用 weekly.timer 和 api.service。首次采集必须手动成功；检查 timer、服务状态与日志。
4. 按 deploy/Caddyfile.example 配置已有域名的 DNS、HTTPS 入口；仅代理 /v1/weekly。反向代理按实际负载设置限流。接口一分钟共享缓存，采集锁防并发，失败不覆盖，快照保留七天。API 不运行采集；query 参数不能强制更新。
5. `miniprogram/config.js` 的 transport 保持 https；apiUrl 填真实 HTTPS /v1/weekly 地址。微信公众平台配置对应 request 合法域名，开发者工具开启域名校验后验证。

只读接口本地运行：`.venv/bin/python scripts/api.py`，默认 127.0.0.1:8767。该本地地址只供开发检查，手机不能据此上线。原 scripts/serve.py 是网页预览工具，仍支持本地手动采集，不用于生产。

## 可选微信云开发适配

已提供 cloudfunctions/weekly 只读函数，客户端 transport 改为 cloud，cloudEnv 填实际环境 ID。开发者工具需上传该函数并安装依赖。依赖的实际安装、SDK 兼容性、函数权限和真机调用仍须在所选环境验证；未自动开通云开发。

控制台创建 weekly_public 集合，客户端数据库读写均禁止，仅允许受信任服务端 SDK/管理员维护；审核云函数调用权限，使本 App 用户可调用。函数固定读取 latest 文档，忽略客户端参数，不能触发采集或写数据。

执行 `.venv/bin/python scripts/export_cloud.py > /tmp/weekly-cloud.jsonl`，在控制台导入，按 _id 更新 latest 文档（包含 snapshot 字段）。小程序仅调用函数，不直接访问数据库。导入后检查 updatedAt 和项目数。

此云开发适配仅完成数据读取，不包含自动写云数据库的 Python 凭据集成。若选这条路径，必须另外配置受信任的定时采集与发布任务并验证权限，才能满足电脑关闭后自动更新；手动导入不能算云端定时采集验收通过。第一版优先使用上述已有主机路径，避免为数据库与函数引入额外资源。云开发环境额度、计费和可用性以当前控制台为准，不假设存在永久免费套餐。

- `node --test tests/miniprogram.test.js`

## 微信云端每 5 小时采集（2026-11-18）

已增加 collectWeekly，独立从 GitHub Trending 抓取、校验并在事务中更新 weekly_public/latest；客户端 weekly 只读不触发采集。失败抛错并保留旧榜单。人工摘要沿用已有映射，未知简介保留来源原文，无模型调用。

部署 collectWeekly 时选择云端安装依赖，使用 Node.js 18 或更高运行时，超时建议 60 秒。先以云端测试参数 {} 运行，确认返回 status: updated，再验证客户端同步。禁止小程序端调用此管理函数；代码同时拒绝带微信用户身份的调用。

函数目录 config.json 包含每小时触发一次的定时器。上传函数代码后，还必须右键 collectWeekly 选择“上传触发器”，在控制台核实触发器已启用。Cron 为 0 0 * * * * *，函数通过 UTC epoch 小时数模 5 进行筛选，每隔 5 小时整点采集，其他小时返回 skipped_not_due；避免使用每天重置的 */5 小时表达式造成午夜 4 小时间隔。控制台手动测试会立即采集，不受整点筛选限制。

北京时间运行时刻按连续 5 小时间隔跨天移动，不是每天固定 5 个时刻。触发可能存在平台延迟；失败会在下一个采集时点再次尝试，没有密集重试。每月约 720 次轻量检查、其中约 144 次采集；实际资源消耗以控制台账单为准。保留按量付费及自动续费关闭。

前端延迟阈值调整为 6 小时。此云端路径只维护最近成功快照，未启用 7 天历史归档；原 Linux 路径仍提供历史归档。实际云端 GitHub 出口可达性、数据库事务权限及定时日志需部署后验收，不应仅凭本地测试宣称已生效。
