# 微信小程序在线榜单接入设计

状态：本地代码已按设计实施，尚未部署。实施进展、云开发边界和验收步骤见 docs/部署与验收.md。以下保留原始方案。

## 1. 推荐架构

GitHub 官方 Trending 周榜 → 云端定时采集任务（复用 Python）→ 校验、中文摘要与功能标签 → 保存成功快照 → HTTPS 只读接口 → 微信小程序。

云端每小时尝试更新；用户打开页面、下拉刷新时只读取最近一次成功榜单，不触发 GitHub 采集。数据时间由采集成功时间决定，不因用户刷新而改变。所有读者共享同一份榜单。

第一版采用一台支持定时任务的云主机或容器，加自有 HTTPS 域名与有效证书。Python 采集继续使用当前 scripts/update.py / trending.py / labels.py。榜单量小，使用文件快照即可，不要求数据库。部署服务及域名实际费用按所选供应商确认。

## 2. 小程序页面

榜单页继续保留：项目名称、中文一句话总结、右侧彩色功能标签、周增星、搜索、分类、排序和本地收藏。

打开页面：先显示设备缓存；同时拉取最新数据，成功后替换缓存。没有设备缓存时使用随包真实快照，并标注“随包快照”。

下拉刷新：读取云端榜单，不强制采集；成功显示“已同步，数据更新于…”，失败显示“连接失败，正在显示缓存”。

超过 2 小时未更新：显示“数据更新延迟”，保留真实数据时间。该阈值是本项目的设计参数，不代表 GitHub 更新频率。

源码入口：小程序点击项目名称先复制 GitHub 仓库链接并提示在浏览器打开；项目详情保留数据与收藏。网页名称仍可直接打开 GitHub。第一版不依赖 web-view 展示 GitHub 网站。

## 3. 接口约定

下面 example.com 是占位域名，不是已部署服务。

GET https://api.example.com/v1/weekly

HTTP 200 返回：

```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-11-17T23:38:10+08:00",
  "source": "https://github.com/trending?since=weekly",
  "period": "GitHub 本周（来源口径）",
  "projects": [
    {
      "id": "owner/repo",
      "name": "owner/repo",
      "url": "https://github.com/owner/repo",
      "summary": "简洁的中文功能总结",
      "category": "技能框架",
      "color": "#8fcfff",
      "growth": 1234,
      "totalStars": 12345,
      "stars": "12,345",
      "rank": 1
    }
  ]
}
```

示例中的 owner/repo 和数字只是接口结构示意，不用于展示。

服务暂无成功快照时返回 503 和 error；有旧快照时继续返回旧快照及原 updatedAt。前端依据真实更新时间判断延迟。后端可设置短缓存，限制请求频率。开放接口只读，不能通过 URL 参数强制运行采集。

## 4. 服务端改造

1. 复用 scripts/trending.py，保持总 Star 与本周新增 Star 分开解析，不自行推算缺失数值。
2. 采集计划独立运行，每小时一次；并发任务使用锁，失败不覆盖上次成功榜单。
3. 每次更新输出带版本号的完整快照，再原子切换 latest 指针；保留最近 7 天快照便于排错和回退。当前多文件输出应改成从同一个成功快照生成，避免读到不同版本。
4. API 只返回 JSON；仅将榜单接口暴露给外部，不开放工程目录、原始 HTML 或本地虚拟环境。
5. scripts/serve.py 当前是本地预览服务器，不直接作为生产服务器。生产用反向代理或托管入口终止 HTTPS，后端读取快照。
6. 日志记录采集开始、成功、失败及项目数；失败重试有限次，不能通过刷新页面产生采集风暴。

## 5. 中文总结和标签

现有 13 个项目已有人工整理的中文总结与分类。后续新增仓库不能保证都被当前字典覆盖。

第一阶段：维护独立的人工覆盖表，未覆盖项目保留来源简介并标注原文，不伪造中文摘要。

如要无人值守地生成中文总结：在云端采集后增加模型处理，仅为新项目或简介变化的项目生成一句话与一个功能标签；限制可选标签及长度，缓存结果，数字与仓库 URL 不交给模型修改。调用失败保留原文。具体模型、密钥与预算在实施前确定，密钥仅存服务端。

## 7. 微信后台配置与发布顺序

1. 准备实际小程序 AppID，并确认账号具备所需开发和发布权限。
2. 准备云运行环境、域名与证书；根据部署地区及微信后台当前要求完成备案等配置。
3. 部署采集任务，生成第一份真实快照；确认公网 HTTPS 接口可访问。
4. 在小程序后台配置该接口所在的 request 合法域名；具体要求以微信后台和官方网络文档为准。
5. 开发者工具导入工程，填写实际 AppID 与 API 地址。
6. 通过接口联调、体验版真机检查，再提交审核与发布。

localhost / 127.0.0.1 不是手机可访问的云服务地址；开发工具里的跳过域名校验不能作为上线方案。

## 8. 验收标准

- 关闭开发电脑后，小程序仍能获取云端榜单，云端任务继续运行。
- 两台手机读到同一版数据，更新时间来自服务端成功快照。
- 手动刷新小程序不直接触发 GitHub 采集。
- 断网、接口失败或 GitHub 结构变化时，保留旧榜并明确显示状态。
- 总 Star、周增 Star、仓库链接与对应快照一致。
- 中文总结、右侧彩色标签在真机小屏正常显示。
- 搜索、收藏在更新后正常；点击名称复制对应仓库链接。
- AppID 和 API 地址配置完成，不依赖开发模式跳过域名校验。
